                QUEUELESS AI APPOINTMENT SYSTEM - FULL API REFERENCE

1. AUTHENTICATION (Public)
-------------------------------------------------------------------------------

POST /auth/register
  - Register a new patient (role = PATIENT).
  - Request:
    {
      "email": "patient@example.com",
      "password": "Secure123!",
      "firstName": "John",
      "lastName": "Doe",
      "phone": "+233501234567",
      "dateOfBirth": "1990-01-01",
      "gender": "MALE",
      "address": "123 Main St, Accra"
    }
  - Response (201 Created):
    {
      "token": "eyJ...",
      "role": "PATIENT",
      "userId": 1,
      "email": "patient@example.com"
    }

POST /auth/login
  - Login for all roles.
  - Request:
    {
      "email": "patient@example.com",
      "password": "Secure123!"
    }
  - Response (200 OK):
    {
      "token": "eyJ...",
      "role": "PATIENT",
      "userId": 1,
      "email": "patient@example.com"
    }

2. PATIENT ENDPOINTS (Role: PATIENT)
-------------------------------------------------------------------------------

GET /patients/me
  - Get current patient's profile.
  - Response (200 OK): PatientProfileResponse
    {
      "id": 1,
      "email": "patient@example.com",
      "firstName": "John",
      "lastName": "Doe",
      "phone": "+233501234567",
      "dateOfBirth": "1990-01-01",
      "gender": "MALE",
      "address": "123 Main St, Accra",
      "medicalHistory": { ... },
      "createdAt": "2026-08-26T10:00:00Z"
    }

PUT /patients/me
  - Update current patient's profile (only firstName, phone, address allowed).
  - Request:
    {
      "firstName": "Johnny",
      "phone": "+233501234568",
      "address": "456 New St, Accra"
    }
  - Response (200 OK): updated PatientProfileResponse

POST /patients/me/medical-history
  - Upload a medical file (PDF, JPEG, PNG) up to 10 MB.
  - Content-Type: multipart/form-data, key = "file"
  - Response (201 Created):
    {
      "message": "File uploaded successfully",
      "publicId": "qas/medical-history/1/abcd1234"
    }

GET /patients/me/medical-history/download?publicId=...
  - Get a signed download URL for the file (valid for 5 minutes).
  - Request param: publicId (required)
  - Response (200 OK):
    {
      "downloadUrl": "https://res.cloudinary.com/.../signed?...",
      "originalFilename": "test.pdf"
    }

3. DOCTOR ENDPOINTS (Role: DOCTOR)
-------------------------------------------------------------------------------

GET /doctors/me
  - Get current doctor's profile.
  - Response (200 OK): DoctorProfileResponse
    {
      "id": 2,
      "email": "doctor@example.com",
      "firstName": "Jane",
      "lastName": "Smith",
      "specialty": "Cardiology",
      "hospitalId": 1,
      "hospitalName": "Korle Bu Teaching Hospital",
      "consultationDurationMinutes": 30,
      "availableDays": { "MONDAY": ["09:00-12:00"] }
    }

PUT /doctors/me/availability
  - Update doctor's available days and time slots.
  - Request:
    {
      "availableDays": {
        "MONDAY": ["09:00-12:00", "14:00-17:00"],
        "WEDNESDAY": ["09:00-12:00"]
      }
    }
  - Response (200 OK): updated DoctorProfileResponse

PUT /doctors/me/consultation-duration
  - Set consultation duration.
  - Request:
    {
      "consultationDurationMinutes": 45
    }
  - Response (200 OK): updated DoctorProfileResponse

GET /doctors/me/schedule?dateFrom=2026-09-01&dateTo=2026-09-07
  - Get schedule for a date range.
  - Response (200 OK): List<DoctorScheduleResponse>
    [
      {
        "date": "2026-09-01",
        "appointments": [ AppointmentResponse, ... ],
        "availableSlots": [ "09:00", "09:30", ... ]
      }
    ]

GET /doctors/me/appointments?status=CONFIRMED&date=2026-09-01
  - Get filtered appointments for the current doctor.
  - Response (200 OK): List<AppointmentResponse> (same as patient's)

PATCH /doctors/appointments/{appointmentId}/status?status=COMPLETED&actualWaitTime=25
  - Update consultation status (COMPLETED or NO_SHOW) and optional actual wait time.
  - Response (200 OK): AppointmentResponse with updated status/timestamps

4. ADMIN ENDPOINTS (Role: ADMIN)
-------------------------------------------------------------------------------

--- Hospitals ---

POST /admin/hospitals
  - Create a hospital.
  - Request: HospitalCreateRequest
    {
      "name": "Korle Bu Teaching Hospital",
      "address": "Accra, Ghana",
      "latitude": 5.5353,
      "longitude": -0.2130,
      "phone": "+233302665421",
      "email": "info@korlebu.gh"
    }
  - Response (201 Created): HospitalResponse

PUT /admin/hospitals/{hospitalId}
  - Update hospital.
  - Request: same as above (all fields optional but recommended)
  - Response (200 OK): updated HospitalResponse

DELETE /admin/hospitals/{hospitalId}
  - Delete hospital (if no doctors/departments depend on it).
  - Response: 204 No Content

--- Departments ---

POST /admin/hospitals/{hospitalId}/departments
  - Create a department under a hospital.
  - Request: DepartmentCreateRequest
    {
      "name": "Cardiology Unit",
      "specialty": "Cardiology",
      "estimatedConsultationDurationMinutes": 30
    }
  - Response (201 Created): DepartmentResponse

PUT /admin/departments/{departmentId}
  - Update department.
  - Request: same as above
  - Response (200 OK): updated DepartmentResponse

DELETE /admin/departments/{departmentId}
  - Delete department.
  - Response: 204 No Content

--- Appointments (Admin oversight) ---

GET /admin/appointments?status=PENDING&departmentId=1&doctorId=2&dateFrom=2026-09-01&dateTo=2026-09-30&page=0&size=20

PATCH /admin/appointments/{appointmentId}/approve?doctorId={doctorId}

  - Response (200 OK): updated AppointmentResponse (status=APPROVED)

PATCH /admin/appointments/{appointmentId}/reject

7. QUESTION & ANSWER ENDPOINTS (Patient & Doctor)
-------------------------------------------------------------------------------

Patient asks a question:
POST /appointments/{appointmentId}/questions
  - Role: PATIENT (must own the appointment)
  - Request:
    {
      "question": "Should I take my medication before the appointment?"
    }
  - Response (201 Created): QuestionResponse
    {
      "id": 1,
      "appointmentId": 1,
      "patientId": 1,
      "patientName": "John Doe",
      "doctorId": 2,
      "doctorName": "Jane Smith",
      "question": "Should I take my medication before the appointment?",
      "answer": null,
      "answeredAt": null,
      "createdAt": "2026-08-26T10:00:00Z",
      "updatedAt": "2026-08-26T10:00:00Z"
    }

GET /appointments/{appointmentId}/questions
  - Get all questions for an appointment (patient or doctor involved can access).
  - Role: PATIENT (must own) or DOCTOR (must be assigned)
  - Response (200 OK): List<QuestionResponse>

GET /appointments/{appointmentId}/questions/{questionId}
  - Get a specific question.
  - Role: PATIENT (must own) or DOCTOR (must be assigned)
  - Response (200 OK): QuestionResponse

Doctor answers a question:
POST /appointments/{appointmentId}/questions/{questionId}/answer
  - Role: DOCTOR (must be assigned to the appointment)
  - Request:
    {
      "answer": "Yes, take it as prescribed."
    }
  - Response (200 OK): updated QuestionResponse with answer and answeredAt

8. ERROR RESPONSES (Common across all endpoints)
-------------------------------------------------------------------------------

All error responses follow this structure:

{
  "timestamp": "2026-08-26T10:00:00Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed: requestedDate must be in the future",
  "path": "/api/appointments"
}

Common status codes:
  - 200 OK: success
  - 201 Created: resource created
  - 204 No Content: successful deletion/update with no response body
  - 400 Bad Request: validation or client error
  - 401 Unauthorized: missing/invalid JWT
  - 403 Forbidden: authenticated but insufficient role
  - 404 Not Found: resource not found
  - 409 Conflict: duplicate or conflicting data
  - 500 Internal Server Error: unexpected server error
